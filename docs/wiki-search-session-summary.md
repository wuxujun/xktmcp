## 已完成

### 搜索与缓存

- Wiki 搜索缓存键已规范化，包含用户、查询、分类、`top_k` 和资源链接配置；`top_k` 统一限制为 1–20，默认 5。
- 缓存命中日志已使用 PII 安全掩码。
- 本地搜索增加 GSE 分词方案，保留原有 `builtin` 默认行为。
- GSE 查询词去重；正文词项保留重复出现次数，正文词频得分按最多 10 分计。
- 长正文词频计数使用排序后二分查找，单次命中和短字段仍走快速路径。
- 搜索候选使用倒排词项索引，并保留标题完整短语等原始匹配路径。

### GSE 词典与多租户

- 新增 `local.gse_dictionary`，支持 `zh`（简体与繁体，默认值）和 `zh_s`（仅简体）。
- 同类型词典按需共享，不同类型独立缓存。
- GSE 全局 HMM 模型使用一次性初始化，修复 `zh` 与 `zh_s` 并发加载时的数据竞争。
- 租户不继承根配置的分词器或词典选择；每个租户单独规范化。

### 刷新与反向链接

- 刷新过程支持并发保护、快照复用和不可变词项切片复用。
- Markdown 文档修改即使大小和时间戳相同也会重新判断内容，避免复用过期索引。
- 反向链接解析支持相对 Markdown 链接和 `[[wiki link]]`，忽略外链，保留首次上下文、重复标题和自链排除语义。
- 反向链接构建已从全量文档两两匹配改为按路径、标题、PageID、文件 stem 建立候选桶。

### 配置与文档

- `config/wiki.json`：租户 `0002` 当前为 `tokenizer: "gse"`、`gse_dictionary: "zh_s"`；根配置和 `0001` 未改动。
- `config/wiki.example.json` 已补充分词器和词典字段。
- `README.md` 已说明配置、内存影响、租户隔离和重启要求。
- `.env` 未修改，认证 Token 未写入文档或输出。

## 真实语料测量结果（2026-09-12 租户 0002 阶段细分测量）

本地目录为 `/Users/xujunwu/docker_data/comp-wiki/wiki`，共有 419 个 Markdown 文档，正文约 1.07 MB（1,070,089 字节），正文词项槽位 155,517。
使用租户 `0002`（`tokenizer: "gse"`, `gse_dictionary: "zh_s"`）执行 `TestLocalWikiCorpusProfile` 测量：

- `zh_s` 词典初始化：766.9 ms，堆增量 134,981,912 字节（约 128.7 MiB）。
- 快照索引整体构建：431.6 ms（相比优化前的 ~1.1 秒下降约 60%）。
- **反向链接阶段（候选桶机制）**：**14.35 ms**（优化前全量两两匹配耗时 945–964 ms，耗时下降约 **98.5%**，加速 ~66 倍）。
- **倒排词项索引阶段**：**6.62 ms**。
- 快照内存增量：12,794,928 字节（约 12.2 MiB）。
- 热搜索耗时（100 次采样统计）：
  - 首篇标题查询：5 条结果，p50 = 489.2 µs，p95 = 683.7 µs。
  - 中间篇标题查询：5 条结果，p50 = 720.4 µs，p95 = 1.05 ms。
  - 末篇标题查询：5 条结果，p50 = 323.5 µs，p95 = 530.7 µs。
  - 不存在词项查询（`zzxxyywwqq`）：0 条结果，p50 = 868.5 µs，p95 = 944.0 µs。
- 结论：候选桶优化彻底消除了反向链接阶段作为刷新首请求的主要瓶颈（从 ~950 ms 降至 14 ms），整体索引构建已降至约 0.43 秒，无需额外实现更复杂的 PageID 后缀专用缓存。

## 业务词库 zh 与 zh_s 召回比对结果（2026-09-13）

在真实 419 篇 Markdown 语料上，使用 `TestLocalWikiDictionaryComparison` 对比了 GSE `zh`（简繁兼备）与 `zh_s`（仅简体）的召回与排序：

1. **专有名词与赛事**（8 个查询：`PBL`、`约翰洛克`、`Thinktown`、`FBLA`、`NEC`、`沃顿商赛`、`学术顾问`、`科学无国界`）：
   - Top-1 一致率：**100.0%**
   - Top-5 完全一致率：**100.0%**
   - ZH 总召回 35 条 vs ZHS 总召回 35 条（完全一致）。
2. **英文与数字混合**（5 个查询：`1920年代`、`8–10年级`、`800–1000字`、`AP课程`、`PBL写作`）：
   - Top-1 一致率：**100.0%**
   - Top-5 完全一致率：**100.0%**
   - ZH 总召回 24 条 vs ZHS 总召回 24 条（完全一致）。
3. **简体通用业务短语**（5 个查询：`参赛资格`、`评审标准`、`辅导方案`、`历史旅行指南`、`学习产品体系`）：
   - Top-1 一致率：**100.0%**
   - Top-5 完全一致率：**100.0%**
   - ZH 总召回 25 条 vs ZHS 总召回 25 条（完全一致）。
4. **繁体中文**（9 个查询）：
   - Top-1 一致率：**88.9%**，Top-5 一致率：**88.9%**。
   - 典型差异：`query="項目制"`：
     - `ZH`（含繁体）：命中《项目制与学术顾问课程设计》（score=21.0），总召回 5 条。
     - `ZHS`（仅简体）：未收录繁体词条，hits = 0（漏召回）。
5. **决策结论**：
   - 全体 27 个样本中总体 Top-1 与 Top-5 一致率均为 **96.3%**。
   - `zh_s` 可为确定仅使用简体的场景节省 **34.5%** 的堆内存（128.7 MiB vs 196.5 MiB）。
   - 由于繁体查询下 `zh_s` 会出现漏召回，**全局默认词典必须维持 `zh`**。
   - 租户 `0002` 可继续保持 `zh_s` 配置，实现租户级别内存优化，不影响其他租户或根配置的兼容性。

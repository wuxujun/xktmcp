## 1. 远程认证日志与 UserID 提取优化 (`internal/auth/auth.go`)

### 1.1 响应体日志记录
- **响应体读取与日志输出**：在 `doRemoteCall` 方法中，使用 `io.LimitReader(resp.Body, 4096)` 限制最多读取 4KB 响应体，防止超大响应体撑爆内存。
- **日志级别**：验证通过输出 `Infof` 日志，验证拒绝输出 `Errorf` 日志，并在日志中包含脱敏后的 `token`、HTTP `status` 以及响应体 `body`。

### 1.2 UserID 嵌套字段解析支持
- **JSON 结构兼容**：远程验证端点返回的数据结构为 `{"code":0, "success":true, "data":{"userid":"6492"}}`。
- **结构体映射**：更新 JSON Unmarshal 结构体，支持同时解析根节点 `userid` 与嵌套节点 `data.userid`，优先提取 `data.userid`，保证 `userID` 被正确识别。

### 1.3 Context 传递与 MCP SDK 跨层解耦
- **Session 映射机制**：由于 MCP Go SDK 在处理长连接（Streamable HTTP/SSE）时会主动 detach HTTP 请求的 `context`，直接在 HTTP 中间件中注入的 `context` 无法传递到工具 Handler。
- **两层桥接**：
  1. 在 `Authenticator` 内部建立 `sessionUserID sync.Map`（`sessionID` -> `userID`）。
  2. 在 HTTP `Middleware` 中认证成功时将 `sessionID` 与 `userID` 写入 Map。
  3. 提供 `MCPMiddleware()` 注册到 `mcp.Server`（通过 `s.AddReceivingMiddleware`），在 MCP 消息处理层自动从 `Session` 提取 `userID` 并注入到 `trace.WithUserID` 中，使工具 Handler 层可透明获取。

## 2. Student / Staff / RAG 搜索接口动态 UserID 优化

针对 `staff`、`rag` 以及 `student` 相关搜索接口，统一调整为：**当 `userID` 非空时在请求 URL 中追加 `userID` / `userid` 参数；当 `userID` 为空时支持不带该参数正常请求**。

### 2.1 上游客户端 API 调整 (`internal/client/`)
- **`StaffAPI.SearchStaffs`** (`staff_client.go`)：
  - 当 `userId != ""` 时，构造 `?userid={userId}&query={query}`。
  - 当 `userId == ""` 时，仅构造 `?query={query}`。
- **`RagAPI.SearchRags`** (`rag_client.go`)：
  - 当 `userId != ""` 时，构造 `?userId={userId}&query={query}`。
  - 当 `userId == ""` 时，仅构造 `?query={query}`。
- **`StudentAPI` 扩展** (`student_client.go`)：
  - `SearchStudents` / `SearchOrders` / `SearchExam` / `GetStudent` 均新增 `userId` 参数。
  - 当 `userId != ""` 时，在 URL 末尾追加 `&userId={userId}` 或 `?userId={userId}`；当 `userId` 为空时保持原有参数格式。

### 2.2 服务层与工具 Handler 贯穿 (`internal/service/` & `internal/tools/`)
- **`StudentService`** (`student_service.go`)：
  - 方法签名适配：`Search`、`SearchOrders`、`SearchExam`、`Get` 均接收 `userId` 参数并透传给 Client 层，不再强制校验 `userId` 非空。
- **`Student` 工具 Handler** (`student.go`)：
  - Handler 中统一通过 `trace.EffectiveUserID(ctx, args.UserID)` 获取当前的生效 `userID`。
  - 在缓存 Key 中加入 `userID` 维度（如 `student:search:{userID}:{query}:{page}:{pageSize}`），保证不同用户之间的查询缓存相互隔离。

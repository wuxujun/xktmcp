## 一、 项目概述与架构总览

`xktmcp` 是一个基于 Go 1.25 开发的高性能企业级 **MCP 服务端 (Model Context Protocol Server)**。项目旨在为 LLM 大模型（如 Claude、GPT-4）及自动化编排系统（如 n8n、Dify 等）提供安全、稳定、低延迟的数据查询与知识库检索能力。

### 架构设计图
```mermaid
graph TD
    Client[LLM 客户端 / n8n / Dify] -->|Stdio / Streamable HTTP / SSE| Main[cmd/server/main.go]
    Main -->|多因素鉴权 / IP白名单 / 租户ACL| Router[Transport Router & Middleware]
    Router -->|注册统一包装器 addTool| Register[internal/server/register.go]
    
    subgraph Core Tools (MCP Layer)
        T1[student_search / student_get]
        T2[student_order / student_exam]
        T3[rag_search]
        T4[staff_search]
    end
    
    Register --> T1
    Register --> T2
    Register --> T3
    Register --> T4

    subgraph Service & Client Layer
        Svc[Service 业务逻辑与校验]
        Cli[HTTP Client & Backoff Retry]
        Breaker[熔断器 Circuit Breaker]
    end

    T1 & T2 & T3 & T4 --> Svc
    Svc --> Cli
    Cli --> Breaker
    Breaker -->|Upstream API| Backend[后端 HTTP 接口服务]

    subgraph Infra & Security Infrastructure
        Auth[internal/auth - 鉴权与ACL]
        Cache[internal/tools/cache.go - 三重防泄漏内存缓存]
        PII[internal/pii - 脱敏与数据安全]
        Trace[internal/trace - 链式 Trace ID 追踪]
        Metrics[internal/metrics - Prometheus 监控指标]
        Log[internal/logger - 结构化 JSON 审计日志]
    end

    Register -.-> Auth & Trace & Metrics & Log
    T1 & T2 & T3 & T4 -.-> Cache & PII
```

## 二、 已实现的核心功能与 MCP 工具

系统共向 LLM 暴露了 **6 个核心 MCP Tools**，涵盖学生数据管理、知识库 RAG 检索以及员工/机构架构查询。

### 1. 学员数据管理工具链 (`student_*`)
- **`student_search`**：
  - **功能**：根据姓名或手机号等模糊信息分页检索学员基本信息。
  - **关键机制**：返回唯一标识 `id` / `smp_id`，引导 LLM 提取精确 ID 进行后续下钻查询；支持 `page` 与 `page_size` 规范化控制。
- **`student_get`**：
  - **功能**：根据学员精确 ID 获取详细的学员档案与个人数据。
- **`student_order`**：
  - **功能**：根据学员精确 ID 查询其购买课程、订单记录及履约状态。
- **`student_exam`**：
  - **功能**：根据学员精确 ID 查询其考试成绩、通过状态及详细成绩表。

### 2. 企业知识库 RAG 检索工具 (`rag_search`)
- **功能**：提供企业知识库语义/关键字检索，返回重组后的上下文（`context`）、切片内容（`chunks`）及来源文档（`sources`）。
- **查询改写 (Query Rewrite)**：
  - **语义改写 (Semantic Rewrite)**：支持通过 MCP Sampling 机制调用客户端大模型将口语提问（如“怎么处理”）自动转换为精准检索词（如“的处理规则”）。具备优雅降级与能力探测机制，对于不支持 Sampling 的客户端（如 n8n）自动切回本地正则改写。
  - **控制开关**：可通过环境变量 `RAG_SEMANTIC_REWRITE` 快速开关。
- **灵活响应控制**：支持 `top_k`、`min_score`、`include_sources`、`include_chunks` 等参数定制。

### 3. 员工与组织机构检索工具 (`staff_search`)
- **功能**：提供员工、教师、校区、院系、课程、部门及其关联关系的检索能力，为 LLM 提供组织架构上下文。

## 三、 企业级基础设施与安全机制

项目不仅实现了业务 Tool，还围绕安全性、稳定性、可观测性构建了完整的基础设施：

### 1. 多传输协议与安全鉴权 (`internal/auth`)
- **三传输模式**：支持 `stdio`（本地免鉴权调试）、`http`（Streamable HTTP `/mcp`）和 `sse`（Server-Sent Events `/sse`）。
- **Bearer Token 认证**：常数时间比较（`ConstantTimeCompare`），防止针对 Token 的计时侧信道攻击。
- **多租户 ACL 隔离**：支持 `AUTH_TENANTS` 配置租户白名单工具列表，防止跨租户越权。
- **IP 白名单与防伪造**：配置 `AUTH_IP_ALLOWLIST` 可对指定 CIDR 网段放行；通过 `AUTH_TRUST_FORWARDED_HEADER` 严格管控是否信任 `X-Forwarded-For`。

### 2. 个人敏感信息 (PII) 脱敏体系 (`internal/pii`)
- **响应级脱敏 (`RedactJSON`)**：对返回给 LLM 的 JSON/文本实时打码手机号（保留前3后4）和身份证号（保留前3后4），保护隐私的同时**保留姓名与 ID**，确保 LLM 具备链式推理能力。
- **日志级审计脱敏 (`MaskSubject`)**：在系统日志和审计日志中对姓名及 Key 等标识符进行脱敏，满足强合规留痕要求。

### 3. 三重防泄漏内存缓存 (`internal/tools/cache.go`)
- **TTL 惰性过期**：读取时物理剔除过期条目。
- **Janitor 后台定时清理**：后台 Goroutine 定期扫描清理无引用的过期“孤儿” Key。
- **LRU 刚性容量上限**：采用双向链表控制最大容量（默认 1024），超限时淘汰最久未使用的 Key。
- **用户隔离缓存 Key**：所有 Tool 缓存 Key 均拼接 `userID`（如 `student:search:{userID}:{query}`），彻底隔离多租户/多用户缓存数据。

### 4. 容错与熔断机制 (`internal/client/breaker.go`)
- **三状态熔断器 (Closed / Open / Half-Open)**：连续 5 次上游网络/5xx 错误即触发 Open 状态，冷却 10 秒后半开探测。
- **智能错误识别**：自动将 4xx 业务错误识别为正常服务响应（不触发熔断），避免业务报错导致服务被误切断。

### 5. 全链路追踪与可观测性 (`internal/trace`, `internal/metrics`, `internal/logger`)
- **请求级 Trace ID**：自动提取/生成 `trace_id` 注入 Go `context`，贯穿 API、Service、Client 和 Logger。
- **Prometheus 指标监控**：暴露 `/metrics` 端点，收集 Tool 调用次数、错误率、响应耗时及 Cache 命中率。
- **结构化 JSON 审计日志**：接入 Lumberjack 实现每日定时轮转与 100MB 自动分卷，打印带短文件路径与行号的高效调试日志。
